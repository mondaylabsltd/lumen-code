# Lumen Code 1.1.1 发布资料

源码提交：`c42c007`（标签 `v1.1.1`，发布分支 `release/v1.1.1`）。协议仍为 1.0，线格式没有改变，与此前的 1.0 版互通。商店提交由账号持有人操作，本轮没有代为提交审核。

这一版的内容：接收更快（实测数据和条件见[性能指南](../../docs/guide/04-performance.zh-CN.md) §4.2）、帧率上限跟随屏幕刷新率、手机横拿时扫描界面跟着转、桌面端新默认值。

1.1.0 只发布了桌面版，一小时后由 1.1.1 取代：1.1.0 的横屏紧凑面板只有 iPhone 有，设置行的标签是右对齐的。商店包没有做过 1.1.0，直接用 1.1.1。

## 已完成

- [桌面正式版下载](https://github.com/mondaylabsltd/lumen-code/releases/tag/v1.1.1)：Windows、Linux x86_64 / ARM64 由 CI 构建；macOS universal / Apple silicon / Intel 三个 DMG 在本机用 Developer ID 签名并公证后上传。
- Android release APK、AAB 已用原上传密钥签名：版本名 1.1.1，versionCode 5，R8 开启。上传证书 SHA-256 `ca42a513a6b89e8a27b89586bc3a453c51ba3ce17e7cbe243ac5319d813f4dad`，与 1.0.1 相同。
- iOS Release archive 已构建：版本 1.1.1，build 4，内嵌提交 c42c007。
- 网站随 `main` 部署。

## 验证情况

| 平台 | 做了什么 |
|---|---|
| iPhone 15 Pro | 同一份源码的调试版真机实测接收（外接 60 Hz 屏和 MacBook 内置 120 Hz 屏），数据见性能指南；1.1.1 的 Release 构建（build 4）已装到这台手机上，装后没有再测 |
| Redmi K40 | 签名 release APK 覆盖升级安装（1.0.1 → 1.1.0 → 1.1.1），启动、进入接收界面、打开相机正常，无崩溃；横屏布局看过截图。**没有测到接收**：测试时手机没有对着屏幕 |
| macOS 桌面 | 本机实测发送（60 Hz 外接屏、120 Hz 内置屏），设置行截图核对 |
| Windows、Linux 桌面 | CI 构建通过，没有在真机运行 |
| 网站 | 类型检查、单元测试、Playwright；用 Chrome 假相机在 844×390 下看过横屏面板，文件 2.1 秒收完。没有用真实相机实测 |

提交 Android 前，建议先在一台 Android 手机上实际收一次文件：接收速率在 Android 上没有测过。

## iOS 导出

```sh
xcodebuild -exportArchive -archivePath src/ios/build/archive/Lumen-1.1.1.xcarchive -exportPath src/ios/build/release/1.1.1 -exportOptionsPlist src/ios/build/export-options-1.1.1.plist -allowProvisioningUpdates
```

1.0.1 时 Xcode 返回过 `PLA Update available`，需要账号持有人先在 Apple Developer 处理待更新协议；这一轮没有重新尝试导出。build 号为 4，同版本再次上传前须增加。
