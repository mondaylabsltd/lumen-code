# Lumen Code 1.2.0 发布资料

源码提交：`2be5fc8`（标签 `v1.2.0`，发布分支 `release/v1.2.0`）。协议仍为 1.0，线格式没有改变，与此前的 1.0 版互通。商店提交由账号持有人操作，本轮没有代为提交审核。

这一版的内容：网页接收端重做（Safari 上约 100 → 平均 399 KB/s，Android 的 Chrome 从解不出到平均 295 KB/s）、接收时的提示（相机跟得上的发送帧率；格子太小时提示靠近或降低密度）、桌面端每帧找码、Android 应用的识别框和对焦。实测数据和条件见[性能指南](../../docs/guide/04-performance.zh-CN.md) §4.5 之后和 [STATUS](../../docs/STATUS.md) §15–17。

- [桌面正式版下载](https://github.com/mondaylabsltd/lumen-code/releases/tag/v1.2.0)：Windows、Linux x86_64 / ARM64 由 CI 构建；macOS universal / Apple silicon / Intel 三个 DMG 在本机用 Developer ID 签名并公证后上传。

## 验证情况

| 平台 | 做了什么 |
|---|---|
| 网站，iPhone 15 Pro 的 Safari | 开发服务器上真机实测，对 60 Hz 显示器：发送 30 帧/秒平均 248 KB/s，20 帧/秒平均 399 KB/s。之后加入的 Android 相关改动对 WebKit 不生效（有单元测试），维护者在其后用过并认为正常；没有再留数据 |
| 网站，Galaxy S22 的 Chrome | 开发服务器上真机实测：平均 295 KB/s（格子 3.5–3.9 像素，发送 20 帧/秒） |
| 网站，Redmi K40 的 Chrome | 真机实测：格子 7 像素（发送端密度"低"）时平均 78 KB/s；4 像素时解不出，页面提示降低密度 |
| 网站，自动测试 | 类型检查、单元测试、Playwright（Chrome 假相机把文件完整收下，WASM 与 JS 两条路径；内容安全策略无违规） |
| iPhone 15 Pro 应用 | 本轮中途的 Release 构建装过真机，维护者测试后认为速度正常；识别路径与 1.1.1 逐帧结果相同（13 帧对比）。1.2.0 的 archive 没有装机 |
| Redmi K40 应用 | 签名 release 包覆盖安装；横屏识别框截图核对；密度"低"时 133–150 KB/s。对焦改为"对一次并保持"后，维护者尚未反馈 |
| Galaxy S22 应用 | 签名 release 包已安装，没有测 |
| macOS 桌面 | 内置摄像头实测接收：3–4 ms 一次识别，每帧都识别；格子 6 像素以上才解得出（见 STATUS §17） |
| Windows、Linux 桌面 | CI 构建通过，没有在真机运行；相机相关改动（1080p 优先、占用提示）未实测 |

## iOS 导出

ipa 已导出（版本 1.2.0，build 5）。命令：

```sh
PATH=/usr/bin:/bin:/usr/sbin:/sbin xcodebuild -exportArchive -archivePath src/ios/build/archive/Lumen-1.2.0.xcarchive -exportPath src/ios/build/release/1.2.0 -exportOptionsPlist src/ios/build/export-options-1.1.1.plist -allowProvisioningUpdates
```

`PATH` 要这样写：Homebrew 的 rsync 在路径里时，导出在打包一步报 "Copy failed"（Xcode 调用的 rsync 参数它不认）。1.0.1 时遇到过的 `PLA Update available` 这次没有出现。这个 ipa 用于上传 App Store Connect（Transporter 或 Xcode），不能直接装到手机上。build 号为 5，同版本再次上传前须增加。
