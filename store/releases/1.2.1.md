# Lumen Code 1.2.1 发布资料

源码提交：`317c0fb`（标签 `v1.2.1`，发布分支 `release/v1.2.1`）。协议仍为 1.0，线格式没有改变，与此前的 1.0 版互通。商店提交由账号持有人操作，本轮没有代为提交审核。

1.2.1 在 1.2.0 之后当晚发布，只多一项：手机应用发送时可以从相册选照片或视频（原来只能打开文件选择器）。桌面版和网站与 1.2.0 相同。1.2.0 的内容和实测数据见 [1.2.0 发布资料](1.2.0.md)。商店包没有提交过 1.2.0，直接用 1.2.1。

## 已完成

- [桌面正式版下载](https://github.com/mondaylabsltd/lumen-code/releases/tag/v1.2.1)：Windows、Linux x86_64 / ARM64 由 CI 构建；macOS universal / Apple silicon / Intel 三个 DMG 在本机用 Developer ID 签名并公证后上传。
- Android release APK、AAB 已用原上传密钥签名：版本名 1.2.1，versionCode 7，R8 开启。上传证书与 1.0.1 相同。
- iOS Release archive 已构建并导出 ipa：版本 1.2.1，build 6，内嵌提交 317c0fb。
- 网站随 `main` 部署。

## 验证情况

| 平台 | 做了什么 |
|---|---|
| Galaxy S22 应用 | 带相册功能的签名 release 包装机实测：从相册选一张照片后进入发送（581 KB 的 JPEG） |
| iPhone 15 Pro 应用 | 带相册功能的 Release 构建已装到真机并启动；相册选择器由维护者试，结果没有反馈给我。照片按原格式发送（HEIC 不转换），文件名按时间生成 |
| Redmi K40 应用 | 这一版没有装机；相册功能与 S22 是同一份代码 |
| 其余 | 与 1.2.0 相同，见 [1.2.0 发布资料](1.2.0.md)的"验证情况" |

iOS 相册选择器不需要相册权限（系统选择器在应用外运行），没有新增权限说明。Android 用系统照片选择器，同样不需要存储权限。

## iOS 导出

```sh
PATH=/usr/bin:/bin:/usr/sbin:/sbin xcodebuild -exportArchive -archivePath src/ios/build/archive/Lumen-1.2.1.xcarchive -exportPath src/ios/build/release/1.2.1 -exportOptionsPlist src/ios/build/export-options-1.1.1.plist -allowProvisioningUpdates
```

`PATH` 的写法见 1.2.0 发布资料。build 号为 6，同版本再次上传前须增加。
